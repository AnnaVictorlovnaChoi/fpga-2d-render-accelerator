## 0. 结论摘要

1. **最新工程**：`v10_Ti60F225_demo_newV1.4`（2026-11-02，697.5 MB）承接 `v9_Ti60F225_demo_new_7cache_HDMI`，
   二者 RTL 模块集合完全一致，差异只在 5 个文件的内容（见 §3.10）。
2. **可保留基线**：`v9`（7 bank cache + HDMI 帧读）与 `v10`（最终版）。
3. **`Ti60F225_demo_Fix2A` 是一条旁支**：它把 `gpu_scale_engine / gpu_scale_x_sampler / gpu_source_cache`
   换成了 `fix2_apb_regs / fix2_control_plane / fix2_frame_control` 三套模块，且 SDC 时间基是“720p/8lane 之前”的旧版，
   **没有合并进 v9/v10**。若要保留这条修复线，只能从未删的 Fix2A 或其两份快照里找回；否则它的价值只剩历史参考。
4. **`backup` 是两个快照**：2026-10-15（28.6 MB，迁移说明 + 废弃 HDMI_Bench 软件与 3 份文档）与
   2026-10-17（583 MB，Fix1A 三缓冲改造前的整工程副本，RTL 模块集合与 v1/v2 相同）。二者都是“旧线”的冗余副本。
5. **若按建议清理**（保留 v9、v10），可释放约 **8.46 GB**（13 个工程/快照合计 8,658 MB），
   其中最大的一项是厂商 DemoBoard 包（1.9 GB）。

## 3. 逐版详情（含证据）

### 3.1 v1_Ti60F225_demo_new（725.0 MB）
- 提交：`8ed43e1 2026-09-29 new board` → `58241f7 2026-10-04 debug done` → `3149605 2026-10-09 sprite,cmdfifo done`。
- 关键文档 `note.md`：定位“提交帧 ≠ 显示帧”造成的整帧撕裂/混叠，明确三帧缓存地址（`0x06000000/0x06200000/0x06400000`，stride 2560），
  `frame_playing / frame_request_frame / frame_pipeline_acquire` 的语义与 RTL `frame_next_user` 复位值。
- 意义：整套游戏平台的软硬件契约在此版定型（三缓冲、PLIC 帧中断、GPIO 帧号）。

### 3.2 v2_Ti60F225_demo_new_bufferfix（559.0 MB）
- 提交：`53cbfe0 2026-10-15 倍频和alpha实现`、`70db9ae 2026-10-15 riscv新版覆盖`。
- RTL 差异：仅 `ddr3_soc_top.v` 内容变化（模块集合与 v1 相同）。
- 解读：所谓 bufferfix 主要发生在 SoC 顶层连线/时钟域整合，而非新增缓冲模块。

### 3.3 v3_Ti60F225_demo_new_720_8lane（622.8 MB）
- 8 个 RTL 文件改写：`GPU_top.v`、`VGA_CTRL.v`、`axi_rgb565_dma.v`、`axi_rgb565_reader.v`、
  `bitblt_cmd_parser.v`、`ddr3_soc_top.v`、`gpu_schduler.v`、`gpu_sync_fifo.v`。
- SDC 新增 37.5 / 74.1 / 370.4 MHz 与 75 MHz，对应 720p 8-lane HDMI 的像素/串行时钟体系。

### 3.4 v4_Ti60F225_demo_new_zoom（883.8 MB）
- 新增 `gpu_scale_engine.v`、`gpu_scale_x_sampler.v`（约 +2 模块），改动 `GPU_top / dma / parser / soc_top`。
- 对应软件侧 OP=4 zoom：线性采样、0.25～4 倍。

### 3.5 v5_Ti60F225_demo_new_fixisr（625.8 MB）
- 改动 `GPU_top / VGA_CTRL / axi_rgb565_writer / parser / soc_top`；SDC 出现 250 MHz 约束。
- 方向：VSYNC 中断与写通道协同（配合 v1 的帧切换结论）。

### 3.6 v6_Ti60F225_demo_newalphasprite（639.4 MB）
- 改动 `GPU_top / axi_rgb565_dma / bitblt_cmd_parser`（模块集合不变）。
- 对应软件侧 OP=5：键控去底与 alpha 混合一次完成（与 v4 zoom 一起构成“6 条指令”的最后两条扩展指令）。

### 3.7 v7_Ti60F225_demo_new_highspeed（582.0 MB）
- 改动 `axi_rgb565_dma.v`、`axi_rgb565_writer.v`；新增验证台 `tb_axi_rgb565_writer_preload.sv`。
- 方向：AXI 写突发与预取提速（对应文档中“single outstanding → 多 outstanding”的演进）。

### 3.8 v8_Ti60F225_demo_new_AXIupdate（650.4 MB）
- 改动 8 个文件（GPU_top、dma、reader、writer、parser、soc_top、scheduler、sync_fifo）；
- **新增 `gpu_source_cache.v`（4 bank）**，并保留 `axi_rgb565_writer.dualbank.bak.v`；
- SDC `core_clk = 4.000 ns`（250 MHz）。
- 意义：源图 cache 机制首次进入 RTL，为 v9 扩到 7 bank 做准备。

### 3.9 Ti60F225_demo_Fix2A（853.1 MB，旁支）
- 模块集合 = v1/v2 的 54 个 + 7 个 `fix2_*`（`fix2_apb_regs`、`fix2_control_plane`、`fix2_frame_control` 及 3 个 testbench），
  同时缺少 v4 的 zoom 与 v8 的 cache；
- SDC 无 37.5/74.1/370.4 MHz，说明它停在 720p/8lane 改造之前的时序基线上；
- `.git` 只有 v1 的 3 个提交，修复本身未提交；
- 两份微快照（`before_timing_sw`、`before_top_integration`）仅含 `par/rtl/SHA256.csv`。
- 结论：这是“帧控制/APB 重构”的一次独立尝试，**没有被 v9/v10 继承**。

### 3.10 v9_Ti60F225_demo_new_7cache_HDMI（675.1 MB，保留）
- `gpu_source_cache.v`：`for(b=0;b<4)` → `for(b=0;b<7)`，`reg [1:0] bank` → `reg [2:0] bank`（4 → 7 bank）；
- 改动 `axi_frame_reader.v`、`ddr3_soc_top.v`、`gpu_schduler.v`、`gpu_source_cache.v`；
- 意义：7 路源缓存 + HDMI 帧读取，是文档中“7bank 16Kb cache”的来源。

### 3.11 v10_Ti60F225_demo_newV1.4（697.5 MB，最新）
- 相对 v9 仅 5 个文件内容变化：`GPU_top.v`、`axi_rgb565_dma.v`、`axi_rgb565_writer.v`、`bitblt_cmd_parser.v`、`gpu_scale_x_sampler.v`；
- 模块集合与 v9 完全相同；SDC/时钟体系不变（core 250 MHz，7 bank）。
- 意义：最终交付版，游戏 G2.25 资源与显示策略即以此工程为准。
