# FPGA 2D 图形渲染加速引擎（RISC-V + 自研 2D GPU 异构架构）

> 2026 全国大学生 FPGA 创新设计竞赛 · **全国三等奖**
> 平台：易灵思（Efinix）Titanium **Ti60F225**
> 语言/工具：Verilog / SystemVerilog、C、Python、Efinix Efinity

在**一片 FPGA 内部**同时集成 RISC-V 软核与一颗自研 2D 图形渲染加速器（2D GPU），
让 CPU 只负责指令组织与任务提交，把像素级的填充、搬移、混合、缩放全部交给硬件并行完成。
系统运行在 **300 MHz**，实现 **1280×720 @ 60 Hz** 实时 2D 渲染，**整机全逻辑独立运行，不需要连接上位机**。

---

## 1. 这个项目想解决什么问题

在 MCU / 软核上做 2D 界面或轻量 2D 游戏，瓶颈几乎总是同一件事：
**CPU 被像素搬运吃满**。一次全屏填充、一次弹幕精灵叠加、一次带 alpha 的图元合成，
在 300 MHz 的软核上用软件循环实现，帧率会立刻塌掉。

所以本项目的思路是：**把「像素怎么落到显存里」这件事从 CPU 手里拿走**，
做成一组可被指令驱动的硬件单元——CPU 只说"画什么、画在哪"，GPU 负责"怎么画得快"。

## 2. 架构

```
                ┌──────────────────────────────────────────────┐
                │              Ti60F225 (单片 FPGA)             │
                │                                              │
  按键/IO ─────▶│  ┌──────────┐   指令队列   ┌──────────────┐  │
                │  │ RISC-V   │─────────────▶│  2D GPU      │  │
                │  │ 软核     │   (cmd FIFO) │  · 指令解析   │  │
                │  │ 300 MHz  │◀── 中断 ─────│  · 多核渲染   │  │
                │  └──────────┘              │  · 7-bank    │  │
                │        │                   │    源缓存     │  │
                │        │ AXI               └──────┬───────┘  │
                │        ▼                          │ AXI/DMA  │
                │  ┌───────────────┐                ▼          │
                │  │  DDR3 控制器   │◀──── 共享显存 (112 Kb    │
                │  │  (帧缓冲)      │      7×16 Kb bank cache) │
                │  └───────┬───────┘                           │
                │          │                                   │
                │          ▼                                   │
                │  ┌───────────────┐    RGB565    ┌─────────┐  │
                │  │  HDMI 输出     │─────────────▶│ 1280×720│  │
                │  │  (DMA 读显存)  │              │ @60 Hz  │  │
                │  └───────────────┘              └─────────┘  │
                │                                              │
                │  Flash 扩展（32 MB，自定义上电识别）           │
                └──────────────────────────────────────────────┘
```

**四个关键设计点**

1. **CPU / GPU 同片异构**：RISC-V 跑业务逻辑与指令组织，GPU 只认指令、不管业务，
   职责边界清晰；两者通过指令 FIFO 解耦，CPU 提交完就可以继续跑下一帧的逻辑。
2. **双 DMA + 共享显存**：渲染通路与 HDMI 显示通路**都**用 DMA 访问 DDR3，不经过 CPU 搬运；
   峰值总线占用率可达 **100%**，GPU 内部多核并行写入时的总线利用率 **> 90%**。
3. **多核共享 7-bank 源缓存**：把常用源图元（精灵、字体、图块）按局部性缓存在 7 个 bank 上，
   多核共享，显著降低对 DDR 的重复读取。
4. **全独立运行**：自制键盘控制器、IO 扩展与 32 MB Flash 扩展板，并自定义上电识别逻辑，
   程序与资源全部固化在板上，**插上 HDMI 就能玩，不需要电脑**。

## 3. 2D GPU 指令集

| 指令 | 含义 | 用途 |
|---|---|---|
| `colorfill` | 纯色矩形填充 | 清屏、色块背景 |
| `bitblt` | 矩形位块搬运（不混合） | 图块拼接、弹幕矩形搬运 |
| `sprite` | 精灵绘制（带透明色/掩码） | 角色、子弹、UI 元素 |
| `alpha` | 带 alpha 混合的图元 | 半透明遮罩、渐隐 |
| `colorkey` | 指定颜色透明 | 免掩码贴图 |
| `zoom` | 缩放采样（扩展指令） | 弹幕缩放、镜头拉伸 |
| `alphasprite` | 精灵 + alpha 混合（扩展指令） | 半透明动态元素 |

CPU 端可用**低复杂度指令队列算法**在「精灵数量」与「帧率」之间做权衡——
在不严重牺牲可玩性的前提下把渲染压力压在预算内。

## 4. 实测指标

**系统参数**

| 项 | 值 |
|---|---|
| 分辨率 / 刷新率 | 1280×720 @ 60 Hz |
| CPU / GPU 频率 | 300 MHz |
| 显存 | 112 Kb（7 × 16 Kb bank cache） |
| CPU 缓存 | 192 Kb（64 Kb I-cache + 128 Kb D-cache） |
| 系统实测最大带宽 | **> 4.5 Gbps**（GPU + HDMI + CPU 并发访存） |
| 外扩程序空间 | 32 MB（Flash，自定义上电识别） |

**32×32 图元下各指令单帧最大数量**

| 指令 | 单帧最大数量 | 对应 GPU 带宽 |
|---|---|---|
| `colorfill` | 2600 | 2.56 Gbps |
| `bitblt` | 1700 | 3.20 Gbps |
| `sprite` | 1050 | 3.20 Gbps |
| `alpha` | 950 | 2.80 Gbps |
| `alphasprite` | 900 | 2.80 Gbps |

> 16×16 图元下渲染数量约为上表的 **2.5 倍**（`sprite` 可达约 3000 个/帧）。
> 以上为**团队作品实测数据**，细节见 [`docs/技术文档_初赛.pdf`](docs/技术文档_初赛.pdf)。

## 5. 配套软件：两个可玩的完整游戏 + 压力测试

硬件不能只跑分，必须能真的跑起来——所以配套写了两个完整游戏，同时充当不同压力场景的基准：

| Demo | 玩法 | 压测场景 | 实测 |
|---|---|---|---|
| **《躲避和头脑风暴！》** (`software/game_alabaster_dawn_test`) | 弹幕躲避 + 限时趣味答题 | 全场景 `copy` + 弹幕精灵纯 `bitblt` 矩形搬运 + 矩形 alpha 混合 | 60 fps 下稳定 **700–800** 个精灵 |
| **《皓白初晓》** (`software/game_alabaster_dawn`) | 肉鸽防守（完整攻击动画、敌人差分、道具动作） | 混合方案：10% `bitblt` + 70% 纯 `sprite` + 15% `sprite/alpha` + 5% `zoom` | 60 fps 下稳定 **600–700** 个各类精灵 |

另有独立**压力测试 Demo**，用于摸清各指令的吞吐上限（即第 4 节的表格）。
